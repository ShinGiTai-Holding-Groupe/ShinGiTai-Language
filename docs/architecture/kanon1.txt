1. CEL PRODUKTU
====================================================================

ShinGiTai Language nie jest klasyczną aplikacją do nauki języków.

Nie budujemy systemu:

lekcja -> quiz -> punkty -> następna lekcja

Budujemy platformę edukacyjną, której centralną postacią jest:

HIKARI — OSOBISTY NAUCZYCIEL AI.

Language dostarcza Hikari:

- kursy,
- materiał edukacyjny,
- słownictwo,
- gramatykę,
- ćwiczenia,
- testy,
- egzaminy,
- pamięć pedagogiczną,
- system powtórek,
- narzędzia szybkiej nauki,
- dane potrzebne do prowadzenia ucznia.

Docelowe doświadczenie użytkownika:

„Idę uczyć się z Hikari.”

Nie:

„Idę kliknąć lekcję.”

====================================================================
2. GŁÓWNA FILOZOFIA
====================================================================

Hikari jest nauczycielem.
Language jest platformą edukacyjną.
Learning Core jest źródłem prawdy o procesie nauki.
Assessment Engine chroni wiarygodność ocen.
OdynAI zarządza dostępem do AI, kontekstem i orkiestracją.
RuntimePort jest stabilną granicą wykonawczą.
Shinrei jest jedynym silnikiem AI i właścicielem providerów, modeli oraz inference.

Hikari nie jest chatbotem, dodatkiem ani oknem do LLM.

Hikari:

- diagnozuje,
- prowadzi,
- tłumaczy,
- sprawdza,
- motywuje,
- planuje,
- przeprowadza egzaminy,
- pamięta postępy,
- dobiera kolejne działania.

====================================================================
3. KANONICZNY PRZEPŁYW AI
====================================================================

Language -> OdynAI -> RuntimePort -> Shinrei -> provider/model

Niezmienniki:

- Language nie komunikuje się bezpośrednio z providerem.
- Language nie komunikuje się bezpośrednio z modelem.
- Language nie komunikuje się bezpośrednio z Ollama.
- Language nie omija OdynAI.
- Language nie posiada fizycznego providera AI.
- Shinrei pozostaje jedynym silnikiem wykonującym modele.
- Shinrei nie zna pojęć kurs, lekcja, słówko, mastery, promocja ani egzamin.

6. COURSE ENGINE I COURSE DEFINITION SYSTEM
====================================================================

Kurs nie może być zapisany bezpośrednio w komponentach React ani zaszyty w UI.

Kurs jest wersjonowaną definicją danych.

Hierarchia:

Course
-> Internal Competency Scope
-> External Level Projection
-> Module
-> Chapter
-> Lesson
-> Activity
-> Challenge
-> Exam

Każdy kurs posiada:

- target_language,
- instruction_language variants,
- interface locale support,
- regional variant,
- internal competency requirements,
- external framework mappings,
- communication goals,
- grammar scope,
- vocabulary scope,
- prerequisite graph,
- assessment rules,
- remediation paths,
- content version,
- release version,
- provenance and licensing metadata.

Każdy element treści posiada co najmniej:

content_id
content_version
schema_version
release_id
status
valid_from
deprecated_at

Zasady publikacji:

- rozpoczęta lekcja jest przypięta do konkretnej wersji,
- opublikowana treść jest niemutowalna,
- poprawka tworzy nową wersję,
- wynik zawsze wskazuje wersję treści,
- historyczny egzamin nie zmienia się po aktualizacji kursu,
- migracja między wersjami jest jawna.

12. ASSESSMENT ENGINE I PROMOTION ENGINE
====================================================================

Hikari:

- prowadzi rozmowę,
- wybiera zadania,
- reaguje na odpowiedzi,
- komunikuje wynik,
- wyjaśnia decyzję.

Assessment Engine:

- analizuje evidence,
- stosuje wersjonowaną rubric,
- liczy wynik,
- sprawdza progi,
- zatwierdza zaliczenie,
- zatwierdza lub odrzuca promocję,
- zapisuje uzasadnienie.

Promotion Engine:

- odblokowuje kolejny dział lub poziom,
- tworzy remediation path,
- blokuje nieuprawnioną promocję,
- pozostaje deterministyczny.

Użytkownik może zadeklarować poziom, ale deklaracja jest tylko hipotezą.

Proces startowy:

user declaration
-> Hikari interview
-> adaptive tasks
-> Learning Evidence
-> Assessment
-> verified starting point

Proces promocji:

learning path
-> end-of-section assessment
-> evidence validation
-> promotion decision
-> next section/level unlock

17. PEDAGOGICAL MEMORY
====================================================================

Własność pamięci:

Language owns durable pedagogical memory.
OdynAI owns memory-access policy and context projection.
Hikari consumes selected pedagogical context.
Shinrei stores no durable student memory.

Pedagogical Memory nie jest swobodnym tekstem modelu.

Ustrukturyzowane rekordy:

StudentGoal
LearningPreference
RecurringError
ObservedStrength
InterventionResult
ExamHistory
MotivationSignal
TeacherObservation

Status obserwacji:

PROPOSED
VALIDATED
REJECTED
EXPIRED

Model może zaproponować obserwację.
Language decyduje, czy obserwacja zostanie zapisana jako wiarygodna pamięć.

Użytkownik musi mieć możliwość:

- przeglądania pamięci,
- edycji,
- usunięcia,
- eksportu,
- wyłączenia pamięci długoterminowej.

19. HIKARI HUMAN INTERACTION LAYER
====================================================================

Cel: usunąć IVONA Effect i robotyczny sposób odpowiedzi.

Kontrakt odpowiedzi Hikari posiada dwie projekcje tej samej decyzji nauczycielskiej:

- display_text,
- spoken_text.

Nie muszą być identyczne.

Przykład:

{
  "display_text": "Odpowiedź jest prawie poprawna, ale wymaga zmiany końcówki.",
  "spoken_text": "Prawie. Sens jest dobry, ale końcówka znowu ci uciekła. Spróbuj jeszcze raz.",
  "interaction_profile": {
    "mode": "teacher_feedback",
    "tone": "supportive_firm",
    "response_length": "short"
  },
  "speech_profile": {
    "pace": "calm",
    "energy": "low",
    "pause_style": "conversational"
  }
}

IVONA_EFFECT_BENCHMARK testuje:

- sztuczne formuły,
- automatyczne chwalenie,
- nadmierne listy,
- brak zmiany rytmu,
- czytanie markdownu,
- powtarzanie pytania,
- kończenie każdej odpowiedzi pytaniem,
- nienaturalną mowę.

21. AI USAGE POLICY
====================================================================

Zasada:

deterministic-first
AI-when-pedagogically-useful

Bez AI powinny działać:

- fiszki,
- matching,
- SRS,
- proste quizy,
- checkpointy,
- odblokowywanie,
- kalkulacja wyniku,
- harmonogram powtórek,
- walidacja jednoznacznych odpowiedzi.

AI jest używane do:

- rozmowy,
- elastycznych wyjaśnień,
- writing feedback,
- speaking,
- generowania przykładów kontekstowych,
- interpretacji odpowiedzi otwartych,
- planowania nauczycielskiego na podstawie danych.

Cel:

- niższa latencja,
- mniejsze obciążenie,
- mniejszy koszt,
- mniejsze ryzyko niestabilności,
- zgodność z możliwościami RTX 2060 Super.

27. BEZPIECZNA RELACJA Z HIKARI
====================================================================

Hikari może być naturalna, ciepła i relacyjna, ale nie manipuluje użytkownikiem.

Hikari nie powinna:

- zawstydzać za brak streaku,
- wzbudzać poczucia winy za przerwę,
- udawać biologicznej osoby,
- twierdzić, że cierpi, gdy użytkownik nie wraca,
- wymuszać emocjonalnego przywiązania,
- przedstawiać się jako zastępstwo lekarza, terapeuty lub człowieka w rolach, których nie pełni,
- ukrywać, że ocena była wsparta przez AI.

====================================================================

Learning Core owns:

- educational truth,
- course state,
- evidence,
- progress,
- mastery,
- assessment results,
- promotion state,
- review scheduling,
- durable pedagogical memory.

Hikari owns:

- teacher behavior,
- natural interaction,
- explanation,
- guidance,
- communication of decisions,
- relationship continuity as a product experience.

OdynAI owns:

- AI access,
- context projection,
- memory-access policy,
- governance,
- orchestration,
- limits,
- security.

RuntimePort owns:

- stable execution contract.

Shinrei owns:

- providers,
- models,
- inference,
- runtime capabilities,
- runtime health.

UI owns:

- presentation,
- interaction,
- accessibility,
- visualization.

UI nie posiada logiki edukacyjnej.

33. NIEZMIENNIKI
====================================================================

INVARIANT 1
Hikari jest centralną postacią doświadczenia edukacyjnego.

INVARIANT 2
Learning Core jest źródłem prawdy o stanie nauki.

INVARIANT 3
Model AI nie może samodzielnie zmieniać poziomu, postępu ani mastery.

INVARIANT 4
Assessment Engine zatwierdza promocję na podstawie Learning Evidence.

INVARIANT 5
Żadna logika pedagogiczna nie trafia do Shinrei.

INVARIANT 6
Language korzysta z AI wyłącznie przez:
Language -> OdynAI -> RuntimePort -> Shinrei.

INVARIANT 7
Interface language, instruction language i target language są niezależne.

INVARIANT 8
Quick Learning wpływa na rzeczywisty profil nauki.

INVARIANT 9
Każdy panel UI pokazuje prawdziwy stan produktu.

INVARIANT 10
Nie wolno uznać funkcji za gotową bez testu i persistence.

INVARIANT 11
Każda zmiana postępu wynika z wersjonowanego Learning Evidence.

INVARIANT 12
Pedagogical Memory należy do Language. OdynAI kontroluje dostęp. Shinrei nie przechowuje pamięci ucznia.

INVARIANT 13
Display text i spoken text są oddzielnymi projekcjami tej samej reakcji Hikari.

INVARIANT 14
Opublikowana treść edukacyjna jest niemutowalna. Zmiana tworzy nową wersję.

INVARIANT 15
CEFR, JLPT, HSK, TOPIK i inne poziomy są projekcjami wewnętrznego profilu kompetencji.

INVARIANT 16
AI działa tylko wtedy, gdy wnosi wartość pedagogiczną; podstawowa logika pozostaje deterministyczna.

INVARIANT 17
Każdy rekord edukacyjny posiada user_id i tenant_partition.

INVARIANT 18
Learning Graph nie może być samodzielnie mutowany przez AI.

INVARIANT 19
Wczesny pionowy E2E powstaje przed rozbudową całego produktu.

INVARIANT 20
Relacja z Hikari nie wykorzystuje mechanik manipulacyjnych.

34. ZASADA PRZEWODNIA
====================================================================

Każda nowa funkcja musi odpowiedzieć na pytanie:

„Czy pomaga Hikari być lepszym nauczycielem albo pomaga uczniowi skuteczniej się uczyć?”

Jeżeli nie — funkcja nie należy do głównego produktu.

====================================================================
35. OSTATECZNY CEL
====================================================================

ShinGiTai Language ma być:

AI Teacher Platform

Nie:

language app with AI

Lecz:

language academy led by Hikari

Language jest platformą.
Hikari jest nauczycielem.
Learning Core zarządza edukacją.
Learning Evidence chroni prawdę o postępie.
Assessment Engine chroni wiarygodność ocen.
OdynAI zarządza inteligencją aplikacyjną.
RuntimePort chroni kontrakt wykonawczy.
Shinrei wykonuje modele.

Całość tworzy jeden spójny system nauki języków rozwijany na lata.
