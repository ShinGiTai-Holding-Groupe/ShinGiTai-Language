1. CEL PRODUKTU
====================================================================

ShinGiTai Language nie jest klasyczną aplikacją do nauki języków.

Budujemy platformę edukacyjną, której centralną postacią jest Hikari — osobisty nauczyciel AI.

Language dostarcza Hikari kursy, materiał edukacyjny, słownictwo, gramatykę, ćwiczenia, testy, egzaminy, pamięć pedagogiczną, system powtórek, narzędzia szybkiej nauki i dane potrzebne do prowadzenia ucznia.

Docelowe doświadczenie użytkownika:

„Idę uczyć się z Hikari.”

6. COURSE ENGINE I HIERARCHIA KURSU
====================================================================

Kurs jest wersjonowaną definicją danych, a nie kodem UI.

Poprawna hierarchia:

Course
-> Module
-> Chapter
-> Lesson
-> Activity
-> Challenge
-> Exam

Równoległe mapowania:

Course
|-- Internal Competency Scope
|-- External Framework Mappings

External Framework Mapping nie jest rodzicem Module. Jest wersjonowaną projekcją kompetencji, a nie elementem hierarchii kursu.

Każdy element treści posiada co najmniej:

content_id
content_version
schema_version
release_id
status
valid_from
deprecated_at

Zasady publikacji:

- rozpoczęta lekcja jest przypięta do konkretnej wersji,
- opublikowana treść jest niemutowalna,
- poprawka tworzy nową wersję,
- wynik zawsze wskazuje wersję treści,
- historyczny egzamin nie zmienia się po aktualizacji kursu,
- migracja między wersjami jest jawna.

10. ASSESSMENT ENGINE I PROMOTION ENGINE
====================================================================

Assessment Engine:

- ocenia Learning Evidence,
- stosuje wersjonowaną rubric,
- wydaje AssessmentDecision,
- ustala PASS / FAIL / INCOMPLETE / REVIEW_REQUIRED,
- określa spełnione i niespełnione wymagania,
- nie odblokowuje poziomu ani modułu.

AssessmentDecision musi być integralnościowo zabezpieczona, wersjonowana, audytowalna i przypięta do evidence oraz rubric_version.

Promotion Engine:

- przyjmuje wyłącznie zatwierdzone AssessmentDecision,
- stosuje reguły odblokowania,
- zapisuje transition,
- tworzy remediation path,
- nie może zmienić wyniku Assessment Engine.

Przepływ:

Learning Evidence
-> Assessment Engine
-> signed/versioned AssessmentDecision
-> Promotion Engine
-> level/module transition

12. ACCESSIBILITY I UCZCIWOŚĆ OCENY
====================================================================

Aplikacja musi zapewniać alternatywy dla speaking, listening i innych kanałów, gdy wymaga tego dostępność.

Alternatywne ćwiczenie nie może automatycznie potwierdzać kompetencji, której faktycznie nie zmierzono.

Przykład:

speaking.assessment_status = ACCOMMODATED_NOT_MEASURED

Nie:

speaking_mastery = MASTERED

Dozwolone statusy pomiaru:

ASSESSED
ACCOMMODATED
NOT_ASSESSED
NOT_APPLICABLE
INSUFFICIENT_EVIDENCE

Wewnętrzny profil może być dostosowany, ale zewnętrzna projekcja CEFR/JLPT nie może deklarować pełnej kompetencji w kanale, którego nie zmierzono.

13. PEDAGOGICAL MEMORY
====================================================================

Language owns durable pedagogical memory.
OdynAI owns memory-access policy and context projection.
Hikari consumes selected pedagogical context.
Shinrei stores no durable student memory.

Pedagogical Memory jest zbiorem ustrukturyzowanych rekordów:

StudentGoal
LearningPreference
RecurringError
ObservedStrength
InterventionResult
ExamHistory
MotivationSignal
TeacherObservation

Status obserwacji:

PROPOSED
VALIDATED
REJECTED
EXPIRED

Model może zaproponować obserwację. Language decyduje, czy obserwacja zostanie zapisana jako wiarygodna pamięć.

15. HIKARI HUMAN INTERACTION LAYER
====================================================================

Human Interaction Layer należy do Language w kontekście nauki, ale nie do Learning Core.

Obejmuje:

- interaction intent,
- teacher tone,
- response length,
- rhythm,
- Spoken Response Realizer,
- Conversation Quality Gate,
- IVONA_EFFECT_BENCHMARK.

Kontrakt odpowiedzi może zawierać:

{
  "display_text": "Odpowiedź jest prawie poprawna, ale wymaga zmiany końcówki.",
  "spoken_text": "Prawie. Sens jest dobry, ale końcówka znowu ci uciekła. Spróbuj jeszcze raz.",
  "interaction_profile": {
    "mode": "teacher_feedback",
    "tone": "supportive_firm",
    "response_length": "short"
  },
  "speech_profile": {
    "pace": "calm",
    "energy": "low",
    "pause_style": "conversational"
  }
}

Niezmiennik:

display_text i spoken_text są dwiema projekcjami tej samej decyzji nauczycielskiej, ale nie muszą być identyczne.

IVONA_EFFECT_BENCHMARK testuje sztuczne formuły, automatyczne chwalenie, nadmierne listy, brak zmiany rytmu, czytanie markdownu, powtarzanie pytania, kończenie każdej odpowiedzi pytaniem i nienaturalną mowę.

16. SYNCHRONIZACJA I STAN KANONICZNY
====================================================================

Backend Language owns canonical synchronized learning state.

Client owns:

- local projection,
- pending offline events,
- checkpoints,
- synchronization cursor.

Client clock is never authoritative for ordering.
Server-assigned revision determines accepted order.

Przepływ zdarzenia offline:

LOCAL_PENDING
-> SUBMITTED
-> ACCEPTED
-> APPLIED

albo:

LOCAL_PENDING -> CONFLICTED
LOCAL_PENDING -> REJECTED
LOCAL_PENDING -> QUARANTINED

Learning Events są append-only dla Learning Evidence, assessmentów, promocji i krytycznych zmian postępu.

Każde zdarzenie zawiera co najmniej:

event_id
idempotency_key
user_id
tenant_partition
organization_id, gdy dotyczy
device_id
occurred_at
received_at
server_revision
schema_version
payload

21. NIEZMIENNIKI
====================================================================

INVARIANT 1
Hikari jest centralną postacią doświadczenia edukacyjnego.

INVARIANT 2
Global Hikari Identity Core należy do OdynAI. Language nie tworzy własnej odrębnej Hikari Identity.

INVARIANT 3
Learning Core jest źródłem prawdy o stanie nauki.

INVARIANT 4
Assessment Engine ocenia evidence i wydaje AssessmentDecision. Promotion Engine wyłącznie stosuje zatwierdzoną decyzję.

INVARIANT 5
Każda zmiana postępu musi wynikać z wersjonowanego Learning Evidence.

INVARIANT 6
Language nie zapisuje fizycznego modelu, providera, node ani GPU. Zapisuje audytowalny execution receipt.

INVARIANT 7
Alternatywa accessibility nie może fałszywie potwierdzać niezmierzonej kompetencji.

INVARIANT 8
Backend Language posiada kanoniczny zsynchronizowany stan nauki.

INVARIANT 9
Client clock nigdy nie jest autorytatywny dla kolejności zdarzeń.

INVARIANT 10
Opublikowana treść edukacyjna jest niemutowalna. Zmiana treści tworzy nową wersję.

INVARIANT 11
Pedagogical Memory należy do Language. OdynAI kontroluje dostęp i projekcję kontekstu. Shinrei nie przechowuje pamięci ucznia.

INVARIANT 12
Display text i spoken text są oddzielnymi projekcjami tej samej reakcji Hikari.

INVARIANT 13
Poziom zewnętrzny, taki jak CEFR lub JLPT, jest projekcją wewnętrznego profilu kompetencji.

INVARIANT 14
Language korzysta z AI wyłącznie przez Language -> OdynAI -> RuntimePort -> Shinrei.

INVARIANT 15
UI nie posiada logiki edukacyjnej i nie prezentuje fikcyjnych danych.
